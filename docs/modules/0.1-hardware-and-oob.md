## 1. Objective and scope

At the end of this module the R730xd is a known-good machine: firmware current and
recorded; the iDRAC reachable only on a management link, by one named
administrator with an SSH key, with every unneeded service off; the storage
controller presenting raw disks; every disk mapped from serial to bay; a BIOS
baseline with a working serial console; and a recorded power and thermal baseline.

**In scope:** hardware and license inventory; firmware check and update policy;
iDRAC network, identity, time and protocol surface; BIOS baseline including
Secure Boot and serial redirection; PERC HBA mode; disk bay map; memory fault
isolation; PSU redundancy; power/thermal baseline; configuration export.

**Out of scope:**
- Host OS install and disk layout (done in the same sessions, recorded in
  ADR-0008, but owned by the host OS module).
- mdadm arrays beyond the installer's, `hdd-vg`, thin pools (storage module).
- Network segments, OPNsense, WireGuard (network module). This module uses a
  provisional direct-cable link.
- Integration with FreeIPA, OpenSearch, Prometheus, backup (Phase 1; see §6).
- UPS purchase (ADR-0007 records the open decision).

## 4. Concepts

- **iDRAC (BMC):** a separate computer on the motherboard with its own NIC and
  OS, on standby power. It can power-cycle the host, change BIOS, mount media and
  read the console. Its login is more powerful than host root. iDRAC8 is
  end-of-life: no more security fixes.
- **RACADM:** firmware RACADM (over SSH, used here), remote RACADM (workstation
  binary over HTTPS, needed for file uploads), local RACADM (inside the OS, unused).
- **FQDDs** name components, read right to left:
  `Disk.Bay.2:Enclosure.Internal.0-1:RAID.Integrated.1-1` is bay 2 on the internal
  backplane of integrated controller 1. Bay numbers are slot indexes, not proof of
  physical position.
- **Lifecycle Controller jobs:** iDRAC attributes apply on `set`. BIOS and
  storage attributes only stage a pending value until a job runs at reboot. One
  BIOS job at a time. Jobs and exports run in the background.
- **SEL vs LC log:** the SEL holds hardware events; the LC log holds detailed
  events with message IDs (PDR3, PDR5, PDR8, PDR87 for disks).
- **PERC personalities:** RAID mode builds virtual disks; HBA mode passes disks
  through. The H330 has no cache, so nothing is lost.
- **ECC and training:** single-bit errors are corrected; multi-bit errors are not.
  A DIMM that fails training at POST is mapped out and disappears from inventory.
  Each CPU has four channels: slots 1/5/9, 2/6/10, 3/7/11, 4/8/12.
- **Serial redirection:** `SerialComm` picks the COM port; `SerialPortAddress`
  picks which device sits on it (serial device 1 = rear connector, device 2 =
  iDRAC). Linux COM2 is `ttyS1`.
- **UEFI, ESP, Secure Boot:** firmware boots `shimx64.efi` from a FAT ESP; Secure
  Boot only runs signed code.
- **TCP vs UDP scanning:** TCP gives a clear handshake; UDP silence is ambiguous
  (`open|filtered`). A service can be "open" at the transport level without the
  protocol accepting sessions (RMCP on UDP 623).

## 5. Build procedure (as it should be run)

Every iDRAC command runs from the admin VM. Until step 5.5, use
`ssh root@192.168.0.120 …`; after it, `ssh idrac …`.

### 5.1 Workstation link

```
nmcli connection add type ethernet ifname <bridged-iface> con-name idrac-link \
  ipv4.method manual ipv4.addresses 192.168.0.10/24 ipv6.method disabled
nmcli connection up idrac-link
```

| Part | Meaning |
| --- | --- |
| `type ethernet ifname <iface>` | Wired profile bound to the bridged NIC |
| `con-name idrac-link` | Profile name |
| `ipv4.method manual`, `ipv4.addresses …/24` | Static address on the iDRAC subnet; no DHCP on a direct cable |
| no gateway | Keeps the default route on the NAT adapter |
| `ipv6.method disabled` | Single-stack link |

**Why:** an isolated link never touches the home LAN. **Verify:** `ip -br addr`
shows 192.168.0.10/24 on the bridged NIC. In Fusion, the NIC must be **Bridged**
to the Ethernet adapter by name; NAT never reaches the cable.

### 5.2 First iDRAC access

At the console: F2 → iDRAC Settings → Network: Dedicated NIC, static
192.168.0.120/24, IPv6 off. User Configuration: replace root's default password
(maximum 20 characters).

```
ping -c 3 192.168.0.120
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no root@192.168.0.120 racadm getsysinfo
```

| Part | Meaning |
| --- | --- |
| `ping -c 3` | Three echo requests |
| `-o PreferredAuthentications=password` | No keys on the iDRAC yet |
| `-o PubkeyAuthentication=no` | Don't offer agent keys (they count as failed logins) |
| `racadm getsysinfo` | Firmware, service tag, power state, network |

**Expected:** RAC Information with `Firmware Version`, System Information with
`Service Tag = 5VWPHK2`. **Why first:** proves the path, SSH crypto compatibility
and firmware level in one command. **Verify:** no `no matching host key type`
error (none occurred with RHEL 9 DEFAULT).

### 5.3 Capture the before-state

```
mkdir -p ~/r730xd/evidence && cd ~/r730xd
for c in getsysinfo swinventory hwinventory "license view" getsensorinfo getsel "get iDRAC.NIC" "storage get controllers -o" "storage get pdisks -o" "storage get vdisks"; do
  ssh root@192.168.0.120 "racadm $c" > "evidence/before-$(echo $c | tr ' ' '_').txt"
done
wc -l evidence/before-*
```

| Part | Meaning |
| --- | --- |
| `for c in …; do … done` | One RACADM call per item; quoted items keep their spaces |
| `$(echo $c \| tr ' ' '_')` | Filename from the command, spaces → underscores |
| `> …` | Output to file |
| `wc -l` | Line count per file; a 3-line file is an error message |

**Why:** evidence of the starting point and a diff baseline. **Verify:** no
empty files; review license, NIC selection, DIMM list, sensors, SEL, controller
mode and disks.

### 5.4 Firmware

```
ssh root@192.168.0.120 racadm swinventory | grep -E 'ElementName|Current Version'
```

`grep -E` keeps component names and installed versions. Compare each with Dell
support for 5VWPHK2. Update per ADR-0005 only where a newer package exists for
the exact part. **Verify:** `firmware-baseline.md` filled in.

### 5.5 Named administrator, root disabled

Key: `ssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa_idrac -C "dave-idrac"`.

Password, typed **on its own line**:

```
read -rs NEWPW
echo ${#NEWPW}
```

`read -r -s` reads silently into a variable; `${#NEWPW}` prints its length (≤ 20).
Then:

```
ssh root@192.168.0.120 "racadm set iDRAC.Users.3.UserName dave"
ssh root@192.168.0.120 "racadm set iDRAC.Users.3.Password '$NEWPW'"
unset NEWPW
for kv in Privilege=0x1ff IpmiLanPrivilege=15 IpmiSerialPrivilege=15 Enable=Enabled; do
  ssh root@192.168.0.120 "racadm set iDRAC.Users.3.${kv%%=*} ${kv#*=}"
done
ssh root@192.168.0.120 "racadm sshpkauth -i 3 -k 1 -t '$(cat ~/.ssh/id_rsa_idrac.pub)'"
```

| Part | Meaning |
| --- | --- |
| `Users.3.UserName/Password` | Slot 3 identity; must be set before the other attributes are accepted |
| `Privilege=0x1ff` | All nine privilege bits: Administrator |
| `IpmiLanPrivilege=15`, `IpmiSerialPrivilege=15` | No IPMI access |
| `${kv%%=*}` / `${kv#*=}` | Attribute name / value from `attr=value` |
| `sshpkauth -i 3 -k 1 -t` | Install the public key: user slot 3, key slot 1, key text |

Add the `Host idrac` block (onboarding doc), then:

```
ssh -o PasswordAuthentication=no idrac racadm getsysinfo
ssh idrac racadm get iDRAC.Users.3
ssh idrac "racadm set iDRAC.Users.2.Password '$(openssl rand -base64 15)'"
ssh idrac racadm set iDRAC.Users.2.Enable Disabled
ssh -O exit root@192.168.0.120 2>/dev/null
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no root@192.168.0.120
```

| Part | Meaning |
| --- | --- |
| `-o PasswordAuthentication=no` | Proves key login |
| `get iDRAC.Users.3` | Must show `Privilege=0x1ff` before root is touched |
| `openssl rand -base64 15` | 20 random characters: root can never return with a known password |
| `ssh -O exit` | Close any reused `ControlMaster` connection so the test is real |
| last `ssh` | Must fail: `Permission denied` |

### 5.6 iDRAC time and protocol surface

Temporary NTP server on the VM:

```
chronyc tracking | grep -E 'Reference|Leap'
echo 'allow 192.168.0.120' | sudo tee -a /etc/chrony.conf
sudo systemctl restart chronyd
sudo firewall-cmd --permanent --add-service=ntp && sudo firewall-cmd --reload
```

`chronyc tracking` must show `Leap status : Normal` (the VM itself is synced).
`tee -a` appends to a root-owned file. `--permanent` + `--reload` opens UDP 123.

Settings (record before-state first with `racadm get <group>`):

```
for kv in iDRAC.NTPConfigGroup.NTP1=192.168.0.10 iDRAC.NTPConfigGroup.NTPEnable=Enabled \
  iDRAC.Time.Timezone=UTC iDRAC.IPMILan.Enable=Disabled iDRAC.VNCServer.Enable=Disabled \
  iDRAC.Telnet.Enable=Disabled iDRAC.SNMP.AgentEnable=Disabled iDRAC.WebServer.TLSProtocol=2 \
  iDRAC.IPBlocking.BlockEnable=Enabled iDRAC.IPBlocking.FailCount=5 \
  iDRAC.IPBlocking.FailWindow=60 iDRAC.IPBlocking.PenaltyTime=600 \
  iDRAC.SerialRedirection.Enable=Enabled \
  LifecycleController.LCAttributes.CollectSystemInventoryOnRestart=Enabled; do
  echo -n "${kv%%=*}: "; ssh idrac racadm set ${kv%%=*} ${kv#*=}
done
```

`echo -n` labels each result. `TLSProtocol=2` is "TLS 1.2 only"
(`racadm help iDRAC.WebServer.TLSProtocol`). Each line must end
`Object value modified successfully`. Reasons: ADR-0004.

**Verify:** `ssh idrac racadm getractime; date -u` agree; `sudo chronyc clients`
lists 192.168.0.120; the external checks in ADR-0004 pass;
`get iDRAC.VirtualConsole` shows `EncryptEnable=Enabled`.

### 5.7 BIOS baseline and serial console

```
for g in BIOS.BiosBootSettings BIOS.ProcSettings BIOS.SysProfileSettings BIOS.SysSecurity BIOS.SerialCommSettings; do
  ssh idrac racadm get $g > evidence/before-$g.txt
done
for kv in BIOS.BiosBootSettings.BootMode=Uefi BIOS.ProcSettings.ProcVirtualization=Enabled \
  BIOS.SysProfileSettings.SysProfile=PerfPerWattOptimizedOs BIOS.SysSecurity.AcPwrRcvry=Last \
  BIOS.SerialCommSettings.SerialComm=OnConRedirCom2 \
  BIOS.SerialCommSettings.SerialPortAddress=Serial1Com1Serial2Com2 \
  BIOS.SerialCommSettings.FailSafeBaud=115200 \
  BIOS.SerialCommSettings.ConTermType=Vt100Vt220 BIOS.SerialCommSettings.RedirAfterBoot=Enabled; do
  ssh idrac racadm set ${kv%%=*} ${kv#*=}
done
ssh idrac racadm jobqueue create BIOS.Setup.1-1 -r pwrcycle -s TIME_NOW -e TIME_NA
ssh idrac racadm jobqueue view
```

| Part | Meaning |
| --- | --- |
| `get <group>` | Whole group, so unplanned non-defaults are visible |
| `set …` | Stages pending values |
| `jobqueue create BIOS.Setup.1-1` | Job applying staged BIOS changes |
| `-r pwrcycle` | Power-cycle to run it. **Only because no OS exists yet** |
| `-s TIME_NOW -e TIME_NA` | Start now, no expiry |

**Expected:** `RAC1024: Successfully scheduled a job`, then `Status=Completed`,
`PR19`. **Prove the serial path at POST before going on:** terminal A
`ssh idrac` → `console com2`; terminal B `ssh idrac racadm serveraction powercycle`;
POST text must appear in A. Then Secure Boot as its own job:

```
ssh idrac racadm set BIOS.SysSecurity.SecureBoot Enabled
ssh idrac racadm jobqueue create BIOS.Setup.1-1 -r pwrcycle -s TIME_NOW -e TIME_NA
```

**Verify:** after-dumps match ADR-0006 with no `Pending Value`. After the OS
install: `grubby --update-kernel=ALL --args="console=tty0 console=ttyS1,115200n8"`
and a `r730xd-01 login:` prompt on `console com2`.

### 5.8 Disk inventory and bay map

```
ssh idrac racadm storage get pdisks -o > evidence/pdisks-hbamode.txt
grep -E '^Disk\.Bay|SerialNumber|ProductId|MediaType|State' evidence/pdisks-hbamode.txt
grep -E '^\s+Size' evidence/pdisks-hbamode.txt
```

`-o` gives all properties; `^\s+Size` matches the space-padded field. Expect six
disks, `State = Non-Raid`. Locate LEDs don't work in HBA mode, so with the disks
empty, pull one caddy at a time and run `ssh idrac racadm storage get pdisks`;
the missing FQDD is that slot. With data on the disks, power off first and read
labels one caddy at a time instead. Bays are numbered down each column, left to
right (column 1 = bays 0–2). **Verify:** `disk-bay-map.md` complete, caddies
labeled.

If no disks appear: controller (`storage get controllers -o`), backplane
(`storage get enclosures -o`), then physical seating (drive flush at the caddy's
back edge).

### 5.9 Controller mode

```
ssh idrac racadm storage get controllers -o | grep -iE '^RAID|Mode'
ssh idrac racadm storage get vdisks
```

Expect `CurrentControllerMode = HBA` and `STOR0104: No virtual disks`. If in RAID
mode: clear virtual disks and foreign config, then F2 → Device Settings →
Integrated RAID Controller 1 → Controller Management → Advanced → Switch to HBA
Mode, reboot.

### 5.10 Memory check, power redundancy, baseline

```
ssh idrac racadm get BIOS.MemSettings.SysMemSize
ssh idrac racadm hwinventory | grep 'InstanceID: DIMM'
ssh idrac racadm getsel
```

Read **after POST finishes**. Any missing DIMM or multi-bit error → hardware
runbook §4. Then:

```
ssh idrac racadm get System.Power
ssh idrac racadm set System.Power.RedundancyPolicy 1
ssh idrac racadm getsensorinfo | grep -i redundan
ssh idrac racadm getsensorinfo > evidence/baseline-os-idle.txt
```

Policy 1 = Input Power Redundant (ADR-0007). Expect `Full Redundant`. Record the
baseline per `power-thermal-baseline.md`.

### 5.11 Configuration export

iDRAC runbook §7. Verify valid XML (`xmllint --noout`), masked secrets, and that
the export reflects current settings (for example
`grep 'SNMP.1#AgentEnable'` → `Disabled`). Close the NFS share afterwards.
