## 5.5 Thin pool for VM disks

The LVM tool card is in Part 2, section 5.3. Concepts 4.6 and 4.7 apply.

### Command 16 — create the thin pool

Purpose: one pool that every VM disk will be carved from, leaving space in
the group for snapshots of root (D4).

```
sudo lvcreate --type thin-pool --name vmpool -l 90%FREE --chunksize 512K ssd-vg
```

| Token | Meaning |
|---|---|
| `--type thin-pool` | create a pool, not an ordinary volume |
| `--name vmpool` | pool name (`-n` is the short form) |
| `-l 90%FREE` | take 90% of the group's unallocated space |
| `--chunksize 512K` | the unit the pool allocates in |
| `ssd-vg` | the volume group |

Changes: creates `ssd-vg/vmpool` plus its hidden data and metadata
volumes.

Expected:

```
  Thin pool volume with chunk size 512.00 KiB can address at most 127.00 TiB of data.
  WARNING: Pool zeroing and 512.00 KiB large chunk size slows down thin provisioning.
  WARNING: Consider disabling zeroing (-Zn) or using smaller chunk size (<512.00 KiB).
  Logical volume "vmpool" created.
```

The warnings are advice, not errors. Zeroing means each newly allocated
chunk is wiped before a volume can read it, which costs time on first
write. It is left on so that a new VM disk can never read blocks a deleted
VM left behind. To trade that safety for speed later:
`sudo lvchange -Zn ssd-vg/vmpool`.

Verify:

```
sudo lvs -a -o lv_name,lv_size,data_percent,metadata_percent,lv_attr ssd-vg
sudo vgs ssd-vg
```

Expect `vmpool` at about 1.6 TiB with `Data%` and `Meta%` near zero,
bracketed names `[vmpool_tdata]` and `[vmpool_tmeta]`, and about 180 GiB
under `VFree`. Record the exact `VFree` figure in the runbook.

If it fails: `insufficient free space` cannot happen with a percentage.
`Volume group "ssd-vg" not found` means a typo or a missing `sudo`.

Undo: `sudo lvremove ssd-vg/vmpool` (only while it holds no volumes you
want).

### Command 17 — prove the VM-disk path with a throwaway volume

```
sudo lvcreate --type thin --thinpool vmpool -V 40G -n vm-scratch ssd-vg
ls -l /dev/ssd-vg/vm-scratch
sudo lvremove -y ssd-vg/vm-scratch
```

| Token | Meaning |
|---|---|
| `--type thin` | a thin volume |
| `--thinpool vmpool` | which pool it draws from |
| `-V 40G` | virtual size; capital V, not `-L` |
| `-n vm-scratch` | name |
| `ls -l` | show that the device node exists and where it points |
| `lvremove -y` | remove without asking for confirmation |

Expected: `Logical volume "vm-scratch" created.`, then a symlink line
ending `-> ../dm-9` (the number varies), then `successfully removed`.

This is the command you will run for every VM disk from Module 0.4 on. The
VM is given `/dev/ssd-vg/<NAME>` as a raw disk.

Snapshot commands, for reference (not run in this module):

```
# VM disk (thin): instant, no size needed
sudo lvcreate -s -n vm-a-pre ssd-vg/vm-a
sudo lvconvert --merge ssd-vg/vm-a-pre     # roll back; VM must be shut down
sudo lvremove ssd-vg/vm-a-pre              # or keep the changes and drop the snapshot

# root (thick): needs its own space from the 180 GiB reserve
sudo lvcreate -s -L 20G -n root-pre ssd-vg/root
sudo lvconvert --merge ssd-vg/root-pre     # roll back; takes effect at next boot
```

## 5.6 Virtualization stack

### Command 18 — install the virtualization group

```
sudo dnf group install "Virtualization Host"
```

| Token | Meaning |
|---|---|
| `group install` | install every package in a named group |
| `"Virtualization Host"` | the group; quoted because of the space |

Changes: installs any missing packages (QEMU, libvirt, virt-install and
their dependencies) and marks the group installed.

Expected on this host: the transaction lists the groups and no packages,
then `Complete!`, because the installer had already put the packages on
disk.

If it fails: `Module or Group 'Virtualization Host' is not available`
means AppStream is not being read. The group is defined there, which is why
`--repo=dvd-baseos` alone could not find it.

Verify: `rpm -q qemu-kvm libvirt virt-install` prints three versions.

### Tool card: `systemctl`

| | |
|---|---|
| What it is | Controls systemd, which starts and supervises every service on the host. |
| Use it when | Starting, stopping, enabling or inspecting a service, socket or timer |
| Related | `journalctl -u UNIT` for that unit's log |
| Grammar | `systemctl [options] VERB UNIT...` |
| Help | `man 1 systemctl` |

A **unit** is something systemd manages. The suffix says what kind:
`.service` (a program), `.socket` (a listening socket that starts its
service on first connection), `.timer` (a schedule that starts its
service), `.mount` (from `/etc/fstab`).

| Verb | Does |
|---|---|
| `status UNIT` | state plus the last log lines |
| `start`, `stop`, `restart` | act now; nothing changes at next boot |
| `enable`, `disable` | change what happens at boot; nothing changes now |
| `enable --now`, `disable --now` | both at once |
| `is-active`, `is-enabled` | one-word answers, good for checks |
| `list-units --type=service`, `list-timers` | what is running; what is scheduled |
| `daemon-reload` | re-read unit files and `/etc/fstab` |
| `mask`, `unmask` | make a unit impossible to start; undo that |

"Enabled" and "active" are independent. A service can be running but not
enabled (it will not come back after reboot) or enabled but stopped.

### Command 19 — run libvirt as modular daemons

Purpose: use the RHEL 9 default layout (concept 4.12). On the build day
`sudo systemctl enable --now libvirtd` was run, which started the
deprecated single daemon. This step reverses that and enables the modular
ones. The single daemon and the modular daemons must not both be enabled.

Check first:

```
systemctl is-enabled libvirtd.service virtqemud.socket virtstoraged.socket
```

If `libvirtd.service` says `enabled`, continue. If it says `disabled` and
the other two say `enabled`, skip to the verify step.

```
sudo systemctl disable --now libvirtd.service libvirtd.socket libvirtd-ro.socket libvirtd-admin.socket

for drv in qemu interface network nodedev nwfilter secret storage; do
  sudo systemctl unmask virt${drv}d.service virt${drv}d.socket virt${drv}d-ro.socket virt${drv}d-admin.socket
  sudo systemctl enable virt${drv}d.service virt${drv}d.socket virt${drv}d-ro.socket virt${drv}d-admin.socket
  sudo systemctl start  virt${drv}d.socket virt${drv}d-ro.socket virt${drv}d-admin.socket
done
```

| Token | Meaning |
|---|---|
| `disable --now UNIT...` | stop these units and remove them from boot |
| `for drv in qemu interface ...` | one pass per libvirt driver |
| `virt${drv}d` | the shell substitutes the driver name: `virtqemud`, `virtstoraged`, ... The braces mark where the variable name ends |
| `unmask` | clear any block left on the unit |
| `enable` | start at boot |
| `start ...socket` | listen now; the service itself starts on first use |

Changes: symlinks under `/etc/systemd/system/` removed and created;
`libvirtd` stopped. No VM exists yet, so nothing is interrupted. Defined
pools are kept: both layouts read `/etc/libvirt/storage/`.

Verify:

```
systemctl is-active libvirtd.service
systemctl is-active virtqemud.socket virtstoraged.socket virtnetworkd.socket
```

Expected: `inactive`, then `active` three times.

If it fails: `Unit virtXd.socket not found` means that driver's package is
not installed; note which and carry on, the QEMU, storage and network ones
are what matter.

Undo: the reverse (disable the `virt*` units, enable `libvirtd`), which you
should not need.

### Command 20 — confirm hardware acceleration

```
virt-host-validate qemu
lsmod | grep kvm
ls -l /dev/kvm
```

| Token | Meaning |
|---|---|
| `virt-host-validate qemu` | libvirt's own checklist of what the host needs to run QEMU/KVM guests |
| `lsmod` | list loaded kernel modules |
| `\| grep kvm` | keep lines mentioning kvm |
| `ls -l /dev/kvm` | the device QEMU opens to use KVM |

Read-only.

Expected on this host:

```
  QEMU: Checking for hardware virtualization                 : PASS
  QEMU: Checking if device '/dev/kvm' exists                 : PASS
  QEMU: Checking if device '/dev/kvm' is accessible          : PASS
  ...
  QEMU: Checking for cgroup 'devices' controller support     : WARN
  QEMU: Checking if IOMMU is enabled by kernel               : WARN (... Add intel_iommu=on ...)
  QEMU: Checking for secure guest support                    : WARN
kvm_intel             446464  0
kvm                  1400832  1 kvm_intel
crw-rw-rw-. 1 root kvm 10, 232 ... /dev/kvm
```

The first three lines are the ones that matter. The warnings:

| Warning | Meaning | Action |
|---|---|---|
| cgroup 'devices' | this controller does not exist under cgroup v2, which RHEL 9 uses | none |
| IOMMU disabled | needed only to hand a physical PCI device to a VM | none now. If passthrough is ever wanted: `sudo grubby --update-kernel=ALL --args="intel_iommu=on"` and reboot |
| secure guest | a feature of other CPU families | none |

If it fails: `FAIL` on hardware virtualization means VT-x is off in the
BIOS. Guests would still run, under emulation, many times slower.

### Tool card: `virsh`

| | |
|---|---|
| What it is | The command line for libvirt. Package `libvirt-client`. |
| Talks to | a libvirt daemon, chosen by a connection URI (concept 4.12) |
| Use it when | Anything to do with VMs, their storage pools and virtual networks |
| Related | `virt-install` (create a VM), `virt-host-validate`, `qemu-img` (disk image files) |
| Grammar | `virsh [-c URI] SUBCOMMAND [arguments]` |
| State | `/etc/libvirt/qemu/*.xml` (VMs), `/etc/libvirt/storage/*.xml` (pools), `/etc/libvirt/qemu/networks/*.xml` |
| Help | `virsh help`, `virsh help pool-define-as`, `man 1 virsh` |

| Family | Subcommands |
|---|---|
| Connection | `uri`, `version`, `nodeinfo` |
| Guests ("domains") | `list --all`, `start`, `shutdown` (asks the guest to power off), `destroy` (cuts the power; does not delete anything), `reboot`, `console`, `dominfo`, `domblklist`, `domiflist`, `dumpxml`, `edit`, `define FILE`, `undefine`, `autostart` |
| Storage pools | `pool-list --all`, `pool-define-as`, `pool-build`, `pool-start`, `pool-autostart`, `pool-info`, `pool-refresh`, `pool-destroy` (stop), `pool-undefine` |
| Volumes | `vol-list POOL`, `vol-info`, `vol-delete` |
| Networks | `net-list --all`, `net-define`, `net-start`, `net-autostart`, `net-destroy`, `net-undefine` |
| Snapshots | `snapshot-create-as`, `snapshot-list`, `snapshot-revert` |

Three states apply to guests, pools and networks alike and are set
separately: **defined** (the configuration is saved), **started** (it is
running now), **autostart** (it starts at boot). In libvirt's vocabulary
`destroy` means "stop now" and `undefine` means "forget the
configuration". Neither deletes data.

### Command 21 — make `virsh` talk to the system hypervisor as dave

Purpose: without this, `virsh` run as dave connects to a private per-user
instance and everything you define is invisible to the real hypervisor.
That is what happened to the first `isos` pool on the build day.

```
sudo usermod -aG libvirt dave
echo 'export LIBVIRT_DEFAULT_URI=qemu:///system' >> ~/.bashrc
```

| Token | Meaning |
|---|---|
| `usermod` | modify a user account |
| `-aG libvirt` | add (`-a`) to supplementary group (`-G`) `libvirt`. Without `-a`, `-G` replaces all your groups |
| `dave` | the account |
| `echo '...' >> ~/.bashrc` | append a line to your own shell start-up file; `>>` appends, and no `sudo` is needed because the file is yours |
| `export NAME=value` | set an environment variable that programs you start will see |

Changes: `/etc/group`, and `~/.bashrc`. Group membership is read at login,
so log out and back in.

Verify, after logging back in:

```
id -nG
virsh uri
```

Expected: `libvirt` appears in the group list, and `qemu:///system`.

If it fails: `virsh uri` printing `qemu:///session` means the variable is
not set in this shell (run `source ~/.bashrc`). `authentication
unavailable` or a password prompt means the group change has not taken
effect (log out fully).

Undo: `sudo gpasswd -d dave libvirt`; delete the line from `~/.bashrc`.

Why this way: `sudo virsh` also works. Group membership plus the variable
is what a team would set up, and it removes the chance of defining
something in the wrong instance.

### Command 22 — define the ISO pool

If a pool named `isos` was defined in the session instance earlier, remove
it there first:

```
virsh -c qemu:///session pool-destroy isos
virsh -c qemu:///session pool-undefine isos
```

Then, in the system instance:

```
virsh pool-define-as isos dir --target /var/lib/libvirt/isos
virsh pool-start isos
virsh pool-autostart isos
```

| Token | Meaning |
|---|---|
| `-c qemu:///session` | connect to that instance for this one command |
| `pool-define-as isos dir` | save a pool definition named `isos` of type `dir` (a plain directory) |
| `--target /var/lib/libvirt/isos` | the directory; here it is the mount point of `hdd-vg/isos` |
| `pool-start` | activate it now |
| `pool-autostart` | activate it at boot |

Changes: writes `/etc/libvirt/storage/isos.xml` and an autostart symlink.

Verify:

```
virsh pool-list --all
virsh pool-info isos
```

```
 Name   State    Autostart
----------------------------
 isos   active   yes
```

`pool-info` should report a capacity near 150 GiB. A capacity near 50 GiB
means the pool is looking at the bare directory on root because
`hdd-vg/isos` is not mounted.

Undo: `virsh pool-destroy isos; virsh pool-undefine isos`.

## 5.7 Disk timeout and scrubbing

### Tool card: `udevadm` and udev rules

| | |
|---|---|
| What it is | The control tool for udev (concept 4.10). Part of `systemd-udev`. |
| Use it when | Writing or debugging a rule; finding out why a device got the name or setting it has |
| Grammar | `udevadm SUBCOMMAND [options] [device]` |
| Rules live in | `/usr/lib/udev/rules.d/` (shipped) and `/etc/udev/rules.d/` (yours; wins on a name clash). Files run in name order, hence the number prefix |
| Help | `man 8 udevadm`, `man 7 udev` |

| Subcommand | Does |
|---|---|
| `info -a -n /dev/sdb` | print the device's attributes and those of each parent. This is where you find what a rule can match on |
| `control --reload` | re-read the rule files |
| `trigger [--action=change] [--subsystem-match=block]` | replay events so rules run against devices already present |
| `test /sys/block/sdb` | dry-run the rules for one device and print what would happen, including syntax errors |
| `monitor` | watch events live |

Rule syntax: comma-separated `KEY operator "value"` pairs on one line.
`==` tests, `=` assigns. Every value is in double quotes.

| Key | Meaning |
|---|---|
| `ACTION` | the event: `add`, `change`, `remove` |
| `SUBSYSTEM` | kind of device: `block`, `net`, ... |
| `KERNEL` | the kernel's name for the device; shell-style patterns allowed |
| `ATTR{file}` | a `/sys` file of this device; with `=` it writes the file |
| `ATTRS{file}` | a `/sys` file of this device or any parent |
| `ENV{NAME}` | a property udev has collected about the device |

### Command 23 — raise the SCSI timeout on the Seagate disks

Purpose: D3. Give a desktop disk time to finish its own error recovery
before the kernel resets it.

```
sudo tee /etc/udev/rules.d/60-raid-disk-timeout.rules >/dev/null <<'EOF'
ACTION=="add|change", SUBSYSTEM=="block", KERNEL=="sd[a-z]", ATTRS{model}=="ST1000DM010*", ATTR{device/timeout}="180"
EOF
sudo udevadm control --reload
sudo udevadm trigger --action=change --subsystem-match=block
```

| Token | Meaning |
|---|---|
| `sudo tee FILE >/dev/null <<'EOF'` | write the rule file as root (as in command 15) |
| `ACTION=="add\|change"` | when a device appears or is re-announced |
| `SUBSYSTEM=="block"` | block devices only |
| `KERNEL=="sd[a-z]"` | whole disks `sda` to `sdz`, not partitions |
| `ATTRS{model}=="ST1000DM010*"` | whose model, read from the parent SCSI device, starts with this; `*` matches the rest |
| `ATTR{device/timeout}="180"` | then write 180 into `/sys/block/<disk>/device/timeout` |
| `udevadm control --reload` | load the new rule |
| `udevadm trigger ...` | apply it to the disks already present |

Changes: one rule file; the timeout of three disks, now and at every boot.

Verify:

```
for s in W9A63479 W9A7NB9T W9A9ZDXL; do
  d=$(basename "$(readlink -f /dev/disk/by-id/ata-ST1000DM010-2EP102_$s)")
  echo "$s $d $(cat /sys/block/$d/device/timeout)"
done
```

| Token | Meaning |
|---|---|
| `readlink -f PATH` | follow the symlink and print the real device, e.g. `/dev/sdd` |
| `basename PATH` | strip the directory, leaving `sdd` |
| `$( ... )` | run the command inside and substitute its output |

Expected: three lines ending `180`. The SSDs stay at the driver default of
90.

If it fails (still 90):

```
sudo udevadm test /sys/block/<SEAGATE_SDX> 2>&1 | grep -iE 'timeout|60-raid|invalid'
```

`<SEAGATE_SDX>` is the middle column printed by the verify loop. A line
such as `invalid key/value pair` points at a quoting mistake in the rule.
On the build day the rule had `KERNEL=='sd[a-z]"` with mismatched quotes,
and udev ignored the whole line without any message on the terminal.

Undo: `sudo rm /etc/udev/rules.d/60-raid-disk-timeout.rules`, reload and
trigger again; the value returns to 90 at next boot.

Confirm the premise of D3, once:

```
sudo smartctl -l scterc /dev/disk/by-id/ata-ST1000DM010-2EP102_W9A63479
```

A disk without error-recovery control answers that the SCT Error Recovery
Control command is not supported. Record the actual output in ADR-0013.

### Command 24 — scrub the array by hand

Purpose: read every stripe and compare data with parity, so hidden bad
sectors are found while the array can still repair them.

Wait for the initial build to finish first (`cat /proc/mdstat` shows no
progress line under the array).

```
MD=$(basename "$(readlink -f /dev/md/hdd)"); echo "$MD"
echo check | sudo tee /sys/block/$MD/md/sync_action
cat /proc/mdstat
```

| Token | Meaning |
|---|---|
| `MD=$( ... )` | find the kernel name behind `/dev/md/hdd` (for example `md124`) and store it in a variable |
| `; echo "$MD"` | print it, so you can see the variable is not empty |
| `echo check \| sudo tee /sys/block/$MD/md/sync_action` | write the word `check` into the array's control file as root. Your shell fills in `$MD` before `sudo` runs |
| `cat /proc/mdstat` | a `check = x.x%` progress line appears |

Changes: starts a background read of the whole array (about two hours).
Nothing on disk is modified by `check`.

When `cat /sys/block/$MD/md/sync_action` prints `idle` again:

```
cat /sys/block/$MD/md/mismatch_cnt
```

Expected: `0`. A non-zero count on RAID5 means data and parity disagreed
somewhere; investigate before trusting the array.

If it fails:

| Message | Cause |
|---|---|
| `Permission denied` | you wrote `sudo echo check > ...`; the redirect ran as dave (concept 4.15) |
| `/sys/block//md/sync_action: No such file or directory` | `$MD` is empty, usually because you set it as dave and then switched to a root shell with `sudo -i` |
| `Device or resource busy` | a rebuild or another check is still running |

Stop a running check: `echo idle | sudo tee /sys/block/$MD/md/sync_action`.

### Command 25 — schedule the weekly scrub

Purpose: RHEL 9 ships the schedule as a systemd timer that is not
necessarily enabled.

```
cat /etc/sysconfig/raid-check
systemctl is-enabled raid-check.timer
sudo systemctl enable --now raid-check.timer
systemctl list-timers raid-check.timer
```

| Token | Meaning |
|---|---|
| `/etc/sysconfig/raid-check` | settings for the scrub script: `ENABLED=yes`, `CHECK=check`, and which arrays to include or skip |
| `raid-check.timer` | the schedule; it starts `raid-check.service`, which runs `/usr/sbin/raid-check` |
| `enable --now` | on at boot and scheduled now |
| `list-timers UNIT` | shows the next run time |

Expected: `list-timers` prints a `NEXT` time. With NTP off the host clock
is only as right as it was set by hand, so the day may be off.

If it fails: `Unit raid-check.timer not found`. Check what the package
ships with `rpm -ql mdadm | grep -i check`.

Undo: `sudo systemctl disable --now raid-check.timer`.

## 5.8 Monitoring

### Tool card: `smartctl` and `smartd`

| | |
|---|---|
| What they are | `smartctl` queries a disk's SMART data and runs self-tests, once. `smartd` is the daemon that does it on a schedule. Package `smartmontools`. |
| Config | `/etc/smartmontools/smartd.conf` |
| Use it when | A disk is suspected, before trusting a second-hand disk, after any I/O error in the log, and routinely via `smartd` |
| Grammar | `smartctl [options] DEVICE` |
| Help | `man 8 smartctl`, `man 5 smartd.conf` |

| Option | Meaning |
|---|---|
| `-i` | identity: model, serial, firmware, capacity |
| `-H` | the disk's own overall verdict |
| `-A` | the attribute table |
| `-a` | all of the above plus the error log and self-test log |
| `-x` | everything, including extended logs |
| `-l selftest`, `-l error`, `-l scterc` | one log |
| `-t short`, `-t long` | start a self-test; it runs inside the disk and you read the result later |
| `-X` | abort a running self-test |
| `-d TYPE` | how to reach the disk. `sat` = a SATA disk behind a SCSI layer, which is every disk on this host |
| `--scan-open` | list the disks it can reach and the `-d` each needs |

On this controller every disk is reachable as `/dev/sdX` (or its by-id
path) with `-d sat`. The scan also lists each disk a second time as
`/dev/bus/0 -d sat+megaraid,<DISK_NUMBER>`, numbered 0 to 5. That form is
not needed here; it exists for controllers that hide the disks.

Reading the attribute table: `VALUE` is normalized health (higher is
better, usually starts at 100 or 200), `THRESH` is the failure line,
`RAW_VALUE` is the real count. For the attributes in concept 4.11, watch
the raw value.

### Command 26 — baseline health of all six disks

```
ls /dev/disk/by-id/ata-* | grep -v part | while read -r d; do
  echo "== $d"
  sudo smartctl -H -A -d sat "$d" | grep -E 'result|Reallocated_Sector|Pending|Uncorrect|CRC|Wear_Level'
done
```

| Token | Meaning |
|---|---|
| `ls /dev/disk/by-id/ata-*` | every SATA by-id name; `*` is a shell wildcard |
| `\| grep -v part` | drop the partition entries (`-v` inverts the match) |
| `\| while read -r d; do ... done` | run the body once per line, with the line in `$d` |
| `smartctl -H -A -d sat "$d"` | health verdict and attribute table |
| `\| grep -E 'a\|b\|c'` | keep only lines matching any of these patterns |

Read-only. Expected: `PASSED` for each disk and zeros in the raw-value
column for reallocated, pending, uncorrectable and CRC. Save the output in
the runbook as the baseline.

The disk in bay 2 (serial S3D2NX0J603337T) dropped off the controller once
on 2026-10-23. Its SMART data on the build day was clean (0 reallocated,
0 CRC errors, wear indicator 98). Give it a full self-test:

```
sudo smartctl -t long -d sat /dev/disk/by-id/ata-Samsung_SSD_850_PRO_1TB_S3D2NX0J603337T
sudo smartctl -l selftest -d sat /dev/disk/by-id/ata-Samsung_SSD_850_PRO_1TB_S3D2NX0J603337T
```

The first command returns at once; the disk estimates about 512 minutes.
Run the second later and look for `Completed without error` on the top
line. `Aborted by host` means something reset the disk mid-test; run it
again and note it.

### Command 27 — create the alert hook

Purpose: one script that both `mdadm` and `smartd` call. Today it writes to
the journal. Module 1.5 changes this one file to notify Alertmanager.

```
sudo tee /usr/local/sbin/disk-alert.sh >/dev/null <<'EOF'
#!/bin/bash
# Called by mdadm as: disk-alert.sh EVENT ARRAY [MEMBER]
# Called by smartd with details in SMARTD_* environment variables
logger -t disk-alert -p daemon.err "event=${1:-smartd} array=${2:-} dev=${3:-${SMARTD_DEVICE:-}} msg=${SMARTD_MESSAGE:-}"
EOF
sudo chmod 755 /usr/local/sbin/disk-alert.sh
```

| Token | Meaning |
|---|---|
| `#!/bin/bash` | run this file with bash |
| `logger` | write a line to the system log |
| `-t disk-alert` | tag the line so it can be found with `journalctl -t disk-alert` |
| `-p daemon.err` | facility and priority (error) |
| `${1:-smartd}` | first argument, or the word `smartd` if there is none |
| `${3:-${SMARTD_DEVICE:-}}` | third argument, else the variable `smartd` sets, else empty |
| `chmod 755` | owner may read, write, execute; everyone else read and execute |

Changes: one new executable file.

Verify: `sudo /usr/local/sbin/disk-alert.sh ManualTest /dev/md/hdd` then
`journalctl -t disk-alert -n 1` shows the line.

### Command 28 — RAID event alerts

```
echo "PROGRAM /usr/local/sbin/disk-alert.sh" | sudo tee -a /etc/mdadm.conf
sudo systemctl restart mdmonitor
sudo mdadm --monitor --scan --test --oneshot
journalctl -t disk-alert --since "-2 min"
```

| Token | Meaning |
|---|---|
| `PROGRAM path` | an `mdadm.conf` keyword: run this program for every event |
| `tee -a` | append to the file as root. Check the file name; a typo creates a new file that nothing reads |
| `systemctl restart mdmonitor` | the monitor service reads the config at start |
| `--monitor --scan` | Monitor mode, all arrays |
| `--test` | send a `TestMessage` event for each array |
| `--oneshot` | check once and exit, instead of running forever |
| `journalctl -t disk-alert --since "-2 min"` | log lines with our tag from the last two minutes |

Expected: four lines, one per array, each containing `event=TestMessage`.

If it fails: no lines. Check `grep PROGRAM /etc/mdadm.conf`, that the
script is executable, and `systemctl status mdmonitor`. If SELinux blocked
it, `sudo ausearch -m avc -ts recent` will show a denial.

Real events use the same path: `Fail`, `DegradedArray`, `RebuildStarted`,
`RebuildFinished`, `SpareActive`.

Undo: remove the `PROGRAM` line and restart `mdmonitor`.

### Command 29 — scheduled SMART monitoring

Purpose: replace the catch-all default with one explicit line per disk,
addressed by a name that does not move.

```
sudo cp -a /etc/smartmontools/smartd.conf /etc/smartmontools/smartd.conf.pre-0.2
sudo sed -i 's/^DEVICESCAN/#DEVICESCAN/' /etc/smartmontools/smartd.conf
ls /dev/disk/by-id/ata-* | grep -v part \
  | sed 's#$# -d sat -a -o on -S on -s (S/../.././02|L/../../6/03) -m <nomailer> -M exec /usr/local/sbin/disk-alert.sh#' \
  | sudo tee -a /etc/smartmontools/smartd.conf
sudo systemctl restart smartd
journalctl -u smartd -n 30 --no-pager
```

| Token | Meaning |
|---|---|
| `cp -a ... .pre-0.2` | keep the original |
| `sed -i 's/^DEVICESCAN/#DEVICESCAN/' FILE` | edit the file in place (`-i`): on lines starting (`^`) with `DEVICESCAN`, put `#` in front, which comments them out |
| `sed 's#$# TEXT#'` | append TEXT to the end (`$`) of every line. `#` is used as the delimiter because the text contains `/` |
| `sudo tee -a FILE` | append the six generated lines |
| `-d sat` | device type |
| `-a` | monitor health, attributes, error log, self-test log |
| `-o on -S on` | turn on the disk's automatic offline data collection and attribute autosave |
| `-s (S/../.././02\|L/../../6/03)` | self-test schedule: short test every day at 02:00, long test on Saturdays (day 6) at 03:00. The pattern is type/month/day/weekday/hour |
| `-m <nomailer>` | send no mail. The text `<nomailer>` is typed exactly as shown; it is a keyword, not a placeholder |
| `-M exec PATH` | run this program when there is something to report |
| `journalctl -u smartd -n 30 --no-pager` | the last 30 log lines of the service |

Changes: `smartd.conf` gains six lines; the default line is commented out.

Expected in the log: six lines like `Device: /dev/disk/by-id/ata-... [SAT],
is SMART capable. Adding to "monitor" list.` and `Monitoring 6 ATA/SATA,
0 SCSI/SAS and 0 NVMe devices`.

If it fails: `Monitoring 12` means the `DEVICESCAN` line is still active.
`Unable to register` or a syntax complaint names the line at fault. Run the
`ls ... | sed ...` part without the `tee` to inspect what it generates.

Test the alert path once: add ` -M test` to the end of one disk's line,
restart `smartd`, and look for a line from `journalctl -t disk-alert`. Then
remove ` -M test` and restart again.

Undo: restore `smartd.conf.pre-0.2` and restart `smartd`.

Why this way: `DEVICESCAN` finds each disk twice on this controller and
uses `sdX` names. Explicit by-id lines survive reordering and say exactly
what is watched.

### Command 30 — make sure the journal survives a reboot

```
ls -d /var/log/journal && journalctl --disk-usage
```

If the directory exists, the journal is already kept on disk. If `ls`
reports no such directory:

```
sudo mkdir -p /var/log/journal
sudo systemctl restart systemd-journald
```

`journalctl` options worth knowing: `-u UNIT`, `-t TAG`, `-k` (kernel
messages), `-b` (this boot; `-b -1` the previous one), `-p err` (errors
and worse), `-f` (follow), `--since "1 hour ago"`, `-n 50`.
