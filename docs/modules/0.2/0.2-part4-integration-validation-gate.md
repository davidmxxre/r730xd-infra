## 6. Integration requirements

Phase 1 does not exist yet, so most rows record what this module leaves
ready for it.

| Shared service | State after 0.2 | Hook left for later |
|---|---|---|
| DNS (1.1) | Not applicable. Hostname `r730xd-01` set locally | — |
| Time (1.1) | NTP off, clock set by hand. Timestamps in logs are approximate | Turn `chronyd` on against the edge once it exists |
| Identity (1.2, 1.3) | Not applicable. Root locked; `dave` is the only account, in `wheel` and `libvirt` | Enrol the host; `libvirt` group membership moves to a directory group |
| Logging (1.4) | Local journal, persistent | Forward the journal; `disk-alert` is the tag to index |
| Metrics (1.5) | None | node_exporter's md collector reads `/proc/mdstat`; thin-pool `Data%` and `Meta%` need a textfile collector |
| Alerts (1.5) | Local only: `smartd` and `mdmonitor` call `/usr/local/sbin/disk-alert.sh`, which logs with tag `disk-alert` | Change that one script to notify Alertmanager. Add alerts for: array degraded, pool above 80%, `/srv/bulk` not mounted |
| Backup (1.6) | None. `hdd-vg/backups` (1 TiB) is reserved as the repository | — |
| Packages | Offline repo at `/srv/bulk/repo/rhel9.5`; `dnf` depends on `/srv/bulk` being mounted | Replace with a mirror or subscription when the host has a network |

Single points of failure, stated plainly:

- One host, one controller, one power supply path, no UPS.
- `pv00` carries root and every future VM disk on RAID5 with no write-hole
  protection yet (ADR-0011).
- A full thin pool stops every VM at once.
- Nothing leaves this box until Module 1.6. RAID is not a backup.

## 10. Resumption notes

**The module in five sentences.** The installer had already put the system
on a RAID5 array of the three SSDs with LVM on top, so this module built
the matching HDD tier: a RAID5 array with write-hole protection, a volume
group, and three XFS filesystems. A copy of the install media lives on
that tier so the offline host can install software. The free SSD space
became a thin pool where each VM disk will be a thin volume that can be
snapshotted instantly, with root kept outside the pool so a full pool
cannot take the host down. KVM and libvirt are installed and checked, and
`virsh` is pointed at the system instance. The desktop-class HDDs get a
longer kernel timeout and a weekly scrub, and SMART and RAID events go to
one alert script that Phase 1 will connect to real alerting.

**Open items**

| Item | Why it matters | Where |
|---|---|---|
| UPS decision | Without it, power loss is the write-hole trigger | ADR-0007 |
| `pv00` has a bitmap, not PPL | Root and all VM disks are exposed to the write hole | ADR-0011; runbook "Convert pv00 to PPL" |
| Bay 2 SSD dropped once | It is a member of the array under root | Runbook "Suspect disk"; finish the long self-test |
| `nofail` on the HDD mounts | A dead HDD array currently blocks boot, and with root locked there is no emergency shell | Part 2, command 12; runbook 3.3 |
| No TRIM to the SSDs | SSDs rely on their own garbage collection | ADR-0014 |
| Thin pool can fill | Stops all VMs | Watch `Data%`/`Meta%` by hand until 1.5 |
| `dnf` needs `/srv/bulk` | No mount, no installs | ADR-0015 |
| NTP off | Log times are approximate | Module 1.1 |
| Secure Boot CA expiry | A `shim` update could stop the host booting | ADR-0006 |

**Fragile or easy to forget**

- `sdX` letters changed during the build when the USB stick was inserted.
  Never use them in a command that writes.
- `virsh` without `LIBVIRT_DEFAULT_URI` set, run as dave, silently talks to
  the wrong instance.
- A mistake in a udev rule produces no message. Always read the value back.
